# Echo Setting Check

사진에서 메아리(에코) 서브스탯 텍스트를 추출 → 폼에서 확인/수정 → 점수 계산까지 처리하는 정적 웹 앱입니다.

## 시작하기 (VSCode)

1. 이 폴더를 VSCode에서 열기
2. 터미널(Ctrl+`)에서 의존성 설치
   ```
   npm install
   ```
3. 개발 서버 실행
   ```
   npm run dev
   ```
4. 터미널에 뜨는 주소(보통 http://localhost:5173)를 브라우저에서 열기

## 프로젝트 구조

```
src/
  components/
    ImageUploader.jsx    # 사진 업로드 + 영역 드래그 선택 + OCR 실행
    ExtractedForm.jsx    # 인식된 스탯 확인/수정 폼
    ScoreDisplay.jsx     # 점수 및 등급(공명 링) 표시
  utils/
    ocr.js               # Tesseract.js 래핑, 텍스트 → 스탯 파싱
    scoreCalculator.js    # 스탯 가중치 기반 점수 계산 (여기서 가중치 튜닝)
  App.jsx                 # 3단계 플로우 조립
  index.css               # 디자인 토큰 (색상/타이포)
```

## 점수 계산 로직 커스터마이징

`src/utils/scoreCalculator.js`의 `STAT_WEIGHTS` 객체에서:
- `weight`: 해당 스탯이 점수에 미치는 비중
- `maxRoll`: 스탯 1회 굴림 기준 이론상 최댓값

실제 게임 데이터에 맞춰 이 값들을 수정하면 점수 산식이 그에 맞게 바뀝니다.

## 여러 장 업로드 규칙

- 한 번에 최대 5장까지 업로드할 수 있습니다 (드래그해서 놓기 또는 파일 선택 다중 선택).
- 각 사진은 자동으로 1920×1080 기준으로 정규화됩니다.
  - 원본이 1920×1080보다 **작으면** 인식 실패로 처리하고 에러 메시지를 보여줍니다.
  - 원본이 그 이상이면 비율을 유지한 채 1920×1080을 꽉 채우도록 잘라 리사이즈합니다 (`src/utils/image.js`의 `normalizeImage`).
- 이름·메인 스탯·서브 스탯 3개 영역은 **`src/config/regions.js`에 고정 좌표로 하드코딩**되어 있습니다.
  모든 사진이 1920×1080으로 정규화된다는 전제이므로, 사용자가 매번 영역을 드래그할 필요 없이 자동으로
  같은 위치를 잘라서 인식합니다.
  - 업로드 후 화면에 표시되는 색깔 점선 박스는 실제로 이 좌표가 어디를 가리키는지 보여주는
    **미리보기**입니다. 박스가 실제 스탯 위치와 어긋나 보이면 `regions.js`의 x/y/width/height 값만
    조정하면 됩니다 (드래그 UI는 없습니다).

## OCR 인식률 팁

- 서브스탯 텍스트만 딱 감싸도록 크롭 영역을 좁게 잡을수록 정확도가 올라갑니다.
- `ocr.js`는 `kor+eng` 언어팩을 사용해서 한글 스탯명도 함께 인식합니다.
- 인식된 스탯명은 드롭다운 강제 선택 없이 **텍스트 그대로** 폼에 채워집니다. 목록에 있는 이름을
  입력하면(자동완성 지원) 점수 계산에 반영되고, 목록에 없는 이름은 가중치 미설정으로 표시됩니다.
- 게임 UI의 아이콘 글자가 OCR에 잘못 섞여 들어오는 것을 막기 위해, `sanitizeText`가 한글/영문/숫자/
  `%`/`.`/`-`/`/`/공백을 제외한 모든 문자를 제거합니다. 그래도 이상한 문자가 남으면
  `src/utils/ocr.js`의 허용 문자 정규식을 조정하면 됩니다.
- `%`가 붙어있는 값은 `isPercent: true`로 저장되어 화면에도 `%`가 그대로 표시됩니다.
- 서브 스탯 중 원본 스크린샷에서 노란색으로 하이라이트된 줄은 `src/utils/highlight.js`가 각 줄의
  배경색을 샘플링해서 자동으로 감지하고, 결과 카드에서도 노란 테두리로 표시됩니다. 판별 기준이 화면마다
  다르면 `isYellowish` 함수의 RGB 임계값을 조정하세요.
- OCR은 100% 정확하지 않기 때문에 항상 사람이 확인/수정하도록 설계되어 있습니다.

## % / 소수점 보정 규칙

이 게임은 %가 붙는 서브·메인 스탯이 항상 소수점 한 자리로 표기된다는 규칙이 있습니다. 이를 이용해
`src/utils/ocr.js`의 `parseSingleStat`에서 OCR 오류를 보정합니다.
- 값에 소수점이 찍혀 있으면(예: `12.6`) `%` 기호를 놓쳤어도 무조건 퍼센트 값으로 처리합니다.
- `%` 기호는 읽혔는데 소수점이 없으면(예: `71%`) 마지막 한 자리를 소수점으로 보정합니다(`71` → `7.1`).
- 규칙에 맞지 않는 값이 계속 보이면 `parseSingleStat` 함수의 조건을 조정하세요.

## 배경 잡음(캐릭터 렌더링 등)으로 인식이 잘 안 될 때

`src/utils/image.js`의 `preprocessForOcr`가 OCR에 넘기기 직전에 그레이스케일 변환 + 대비 강화를
적용해서 배경이 비칠 때 생기는 잡음을 어느 정도 줄여줍니다. 다만 이건 완전한 해결책은 아니고, 배경이
아주 밝거나 텍스트와 색 대비가 약하면 여전히 오인식이 날 수 있습니다. 인식률을 더 올리고 싶다면:
- `CONTRAST` 값(현재 1.6)을 더 키워보기
- 크롭 영역(`src/config/regions.js`)을 텍스트에 더 딱 맞게 좁히기
- 가능하면 배경 렌더링이 옅은 스크린샷을 사용하기

## 값 입력 방식 (자유 텍스트)

값 칸은 숫자 입력이 아니라 **텍스트 입력**입니다. OCR이 처음 채워줄 때는 위 보정 규칙에 따라
`7.5%`, `40`처럼 자동으로 넣어주지만, 이후에는 `%`를 직접 붙이거나 지우는 것까지 자유롭게 수정할 수
있습니다. 점수 계산에 다시 연결하려면 `parseFloat`으로 숫자만, `.includes('%')`로 퍼센트 여부를
다시 뽑아내면 됩니다.

## 라벨 띄어쓰기 정규화

OCR마다 "공명효율"/"공명 효율"처럼 띄어쓰기가 들쭉날쭉하게 나오는 문제를 줄이기 위해,
`src/utils/ocr.js`의 `normalizeLabelSpacing`이 `STAT_WEIGHTS`(`src/utils/scoreCalculator.js`)에 있는
정식 스탯명과 공백을 무시하고 비교해서, 일치하면 정식 표기로 맞춰줍니다. `STAT_WEIGHTS`에 없는
낯선 라벨(오인식된 텍스트 등)은 그대로 둡니다 — 카탈로그에 새 스탯명을 추가하면 그것도 자동으로
정규화 대상이 됩니다.

## 결과 화면 구성

- 사진마다 스캔한 부분(이름·메인·서브 스탯을 포함하는 범위)을 리사이즈한 미리보기가 왼쪽에, 그 결과가
  오른쪽에 나란히 표시됩니다. 이름 부분은 더 이상 텍스트로 인식하지 않지만, 눈으로 확인할 수 있도록
  미리보기 이미지에는 포함되어 있습니다.
- 점수 계산 UI는 제거된 상태입니다. `src/utils/scoreCalculator.js`의 `calculateScore`/`scoreTier`는
  코드에 남아있으니, 나중에 다시 붙이고 싶으면 `EchoPanel.jsx`에서 불러다 쓰면 됩니다.

## GitHub Pages 배포

1. GitHub에 새 저장소 생성 후 이 프로젝트 push
2. `vite.config.js`의 `base`를 저장소 이름에 맞게 설정
   ```js
   base: '/저장소이름/',
   ```
3. 배포
   ```
   npm run build
   npm run deploy
   ```
   (`gh-pages` 패키지가 `dist` 폴더를 `gh-pages` 브랜치로 자동 push 합니다)
4. 저장소 Settings → Pages에서 배포된 URL 확인
