# Echo Setting Check

메아리(에코) 스크린샷에서 서브스탯을 자동 추출 → 확인/수정 → 캐릭터별 유효 옵션 기준 점수 통계까지
처리하는 정적 웹 앱입니다.

## 시작하기 (VSCode)

1. 이 폴더를 VSCode에서 열기
2. 터미널(Ctrl+`)에서 의존성 설치
   ```
   npm install
   ```
3. 개발 서버 실행
   ```
   npm run dev
   ```
4. 터미널에 뜨는 주소(보통 http://localhost:5173)를 브라우저에서 열기

## 화면 흐름 (페이지 구조)

```
캐릭터 선택 (시작 화면)
  └ 에코 캡처 (사진 업로드 + 자동 추출)
      └ 수정 (스탯 확인/수정, 사진 교체)
          └ 점수 통계 (유효 옵션만 반영해 점수 계산)
```

- 별도의 메인 페이지나 사이드바 메뉴 없이, 앱을 열면 바로 **캐릭터 선택 화면**이 시작 화면입니다.
- 캐릭터 선택 화면은 캐릭터 사진 + 하단 이름 카드로 구성됩니다. `src/config/characters.js`에
  캐릭터를 추가하면 자동으로 목록에 나타납니다. 사진 추가 방법은 아래 "캐릭터 사진 추가" 참고.
- 캡처 화면에서 사진을 올리면 **버튼을 누를 필요 없이 바로 자동으로 추출되고 곧장 수정 화면으로
  넘어갑니다.** 인식하는 동안에는 화면 전체에 어두운 오버레이와 캐릭터 사진이 도는 로딩 UI가 뜹니다.
- 캡처/수정/점수 통계 화면 어디서든 "← 캐릭터 선택으로" 버튼으로 데이터를 지우지 않고 캐릭터 선택
  화면으로 돌아갈 수 있습니다.
- 수정 화면에서 "점수 통계 보기"를 누르면 통계 페이지로 넘어갑니다.
- 페이지가 바뀔 때마다 살짝 오른쪽에서 밀려 들어오는 전환 애니메이션이 적용됩니다.
- 진행 상태(선택한 캐릭터, 업로드한 에코 세팅)는 **브라우저의 localStorage에 자동 저장**됩니다. 탭을
  닫았다가 다시 열어도 마지막으로 보던 화면과 데이터가 그대로 남아있습니다. 아래 "진행 상태 저장" 참고.

## 여러 장 업로드 규칙

- 한 번에 최대 5장까지 업로드할 수 있습니다 (드래그해서 놓기 또는 파일 선택 다중 선택).
- 각 사진은 자동으로 1920×1080 기준으로 정규화됩니다.
  - 원본이 1920×1080보다 **작으면** 인식 실패로 처리하고 에러 메시지를 보여줍니다.
  - 원본이 그 이상이면 비율을 유지한 채 1920×1080을 꽉 채우도록 잘라 리사이즈합니다 (`src/utils/image.js`의 `normalizeImage`).
- 메인·서브 스탯 2개 영역은 **`src/config/regions.js`에 고정 좌표로 하드코딩**되어 있습니다. 모든
  사진이 1920×1080으로 정규화된다는 전제이므로 사용자가 매번 영역을 지정할 필요가 없습니다. 업로드 후
  표시되는 색깔 점선 박스는 이 좌표가 실제로 어디를 가리키는지 보여주는 미리보기입니다. 어긋나 보이면
  `regions.js`의 x/y/width/height 값만 조정하면 됩니다.

## OCR 인식 및 보정

- `ocr.js`는 `kor+eng` 언어팩을 사용해서 한글 스탯명도 함께 인식합니다.
- 게임 UI의 아이콘이 글자로 잘못 섞여 들어오는 것을 막기 위해 한글/영문/숫자/`%`/`.`/`-`/`/`/공백만
  남기고 나머지는 제거합니다. 낱개 영문자 하나짜리 토큰(아이콘 오인식 흔적)도 걸러냅니다.
- 라벨과 수치가 서로 다른 줄로 쪼개져 인식된 경우(예: "HP" 다음 줄에 "112"만 단독으로 잡히는 경우),
  숫자만 있는 줄을 바로 앞 라벨 줄에 자동으로 합칩니다.
- %가 붙는 값은 항상 소수점 한 자리로 표기된다는 규칙을 이용해 소수점/% 인식 오류를 보정합니다:
  소수점이 있으면 무조건 %, %는 있는데 소수점이 없으면 마지막 자리를 소수점으로 보정합니다(`71%` → `7.1%`).
- OCR에 넘기기 직전 그레이스케일 변환 + 대비 강화를 적용해 배경(캐릭터 렌더링 등)이 비칠 때 생기는
  잡음을 어느 정도 줄입니다(`preprocessForOcr`). 완전한 해결책은 아니라서, 여전히 틀리면 크롭
  영역을 텍스트에 더 딱 맞게 좁히는 게 가장 확실합니다.

## 메인 스탯 보정

메인 스탯은 항상 2줄입니다.
- 첫 줄(코스트 보너스)은 `src/config/mainStatBonusNames.js`의 후보 목록과 편집 거리(레벤슈타인
  거리)로 가장 가까운 이름으로 자동 보정됩니다.
- 둘째 줄(실제 주스탯)은 공격력이 아니면 무조건 HP로 고정됩니다.
- 메인 스탯은 참고용으로만 표시되고 점수 계산에는 반영되지 않습니다.

## 서브 스탯은 고정 카탈로그에서 클릭으로 선택

자유 입력이 아니라 `src/config/subStatOptions.js`의 `SUB_STAT_OPTIONS`에 정의된 조합만 드롭다운으로
고를 수 있습니다. 스탯명을 고르면 그 스탯이 가질 수 있는 고정 수치 목록만 두 번째 드롭다운에
나타납니다. OCR 결과는 `snapSubStatsToCatalog`(`src/utils/ocr.js`)가 가장 가까운 조합으로 자동으로
맞춰주고, 확신이 안 서면 빈 값으로 둬서 사람이 직접 고르게 합니다. 실제 게임 수치와 다르면
`subStatOptions.js`의 배열 값만 고치면 됩니다.

## 캐릭터 사진 추가

1. `npm install --save-dev sharp` (최초 1회, 리사이즈 스크립트가 필요로 함)
2. `raw-characters/` 폴더에 원본 사진 넣기 (파일명이 곧 캐릭터 id가 됩니다. 예: `jiyan.png`)
3. `npm run prepare-characters` 실행 — 새로 넣은 사진을 **고정 크기 610×840**으로 리사이즈해서
   `public/characters/`에 PNG로 저장합니다. `public/characters/`에 들어가는 사진은 항상 이 크기로
   통일됩니다. (평균이 아니라 고정값이라, 몇 장이 있든 결과가 항상 같습니다.)
4. `src/config/characters.js`에 항목 추가:
   ```js
   { id: 'jiyan', name: '지연', image: '/characters/jiyan.png', initials: 'JY', color: '#a78bfa' }
   ```
   (현재는 데니아(deni)/양양·현령(yangyang) 두 캐릭터가 예시로 들어 있습니다.)

## 캐릭터별 유효 옵션 설정

`src/config/characterValidOptions.js`의 `CHARACTER_VALID_OPTIONS`에서 캐릭터 id별로 점수에 반영할
서브스탯 이름 배열을 정의합니다. 여기 없는 스탯은 그 캐릭터 기준으로는 점수에서 제외됩니다.
스탯명은 `subStatOptions.js`의 `SUB_STAT_NAMES`와 철자가 정확히 같아야 합니다.

```js
export const CHARACTER_VALID_OPTIONS = {
  deni: ['크리티컬%', '크리티컬 피해%', '공격력%', '공명 스킬 피해 보너스%', '일반 공격 피해 보너스%'],
  yangyang: ['크리티컬%', '크리티컬 피해%', '공격력%', '공명 효율%', '강공격 피해 보너스%'],
}
```

⚠️ 데니아/양양·현령의 목록은 실제 세팅을 몰라서 채워둔 예시값입니다. 실제로 원하는 유효 옵션을
알려주시면 정확히 맞춰드릴게요.

## 점수 계산 (엑셀 "명조 스펙 계산기"에서 역추적한 실제 공식)

`src/utils/scoring.js`가 점수를 계산합니다. 업로드해주신 엑셀의 수식을 끝까지 따라가서(계산기!R6 →
점수!E36 → 점수!E35 → 점수!E27:E33 → 연산!M36:M51) 실제 캐릭터 데이터로 소수점 둘째 자리까지
정확히 일치하는 걸 확인한 공식입니다:

1. 스탯마다 **값 × 배율을 정수로 내림**한 게 그 스탯의 점수 (크리티컬 1%당 20점, 크리티컬 피해·
   HP%·공격력% 1%당 10점, 방어력%·피해 보너스류 1%당 8점).
2. 유효 옵션인 스탯들의 점수를 더한 게 그 에코의 원점수.
3. **크리티컬%와 크리티컬 피해%를 둘 다 가진 에코 개수 × 2%**를 전체 에코에 공통으로 곱하고, 다시
   정수로 내림.
4. 그 값을 **캐릭터별 이론상 최대치**로 나누고 100을 곱한 게 최종 %점수입니다. 기본값은 690이고,
   시그리카(807)·브렌트(752)·플로로(702)·갈브레나(702)는 예외로 지정돼 있습니다
   (`CHARACTER_MAX_DIVISOR`).

기준을 바꾸려면 `scoring.js`의 `RATE` / `CHARACTER_MAX_DIVISOR`를 수정하면 됩니다.

## 점수 통계 페이지 레이아웃 (3단)

- **왼쪽**: 캐릭터 사진 + 유효 옵션 목록 (고정)
- **가운데 "에코 점수"**: 에코마다 한 줄(사진처럼 압축된 배지+점수)로 나오고, 클릭하면 그 아래로
  서브 스탯 목록이 펼쳐지는 아코디언입니다. 유효 옵션은 노란색, 나머지는 회색으로 표시되며(회색은
  점수에 영향 없음), 라벨 | 값 | 단계가 항상 같은 위치에 오도록 정렬돼 있습니다.
- **오른쪽 "합산 스탯"**: 유효 옵션 여부와 무관하게, 캡처된 모든 서브스탯을 13개 카테고리(HP·
  공격력·방어력·공명 효율·크리티컬·크리티컬 피해·조화도 파괴 증폭·속성 피해 보너스·일반 공격 피해·
  강공격 피해·공명 스킬 피해·공명 해방 피해·에코 피해)로 묶어서, 캡처된 값을 그대로 나열해 보여줍니다.
  아직 캡처 카탈로그에 없는 카테고리(조화도 파괴 증폭·속성 피해 보너스·에코 피해)는 항상 "-"로
  표시됩니다.

맨 위 "← 캐릭터 선택으로" 버튼으로 언제든 처음 화면으로 돌아갈 수 있습니다.

## 노란색 하이라이트

`src/utils/highlight.js`가 서브 스탯 각 줄의 배경색을 픽셀 단위로 샘플링해서 원본 스크린샷에서
노란색으로 강조된 줄인지 판별합니다. 이 값은 각 서브스탯에 `highlighted`로 남아있지만, 점수 계산에는
더 이상 쓰이지 않습니다(캐릭터별 유효 옵션 목록이 그 역할을 대신합니다). 필요하면 `EchoPanel.jsx`나
`StatsPage.jsx`에서 참고용 표시로 다시 활용할 수 있습니다.

## 사진 교체

수정 화면의 각 카드 썸네일 영역 전체가 드롭존입니다 — 클릭해서 파일을 고르거나 새 사진을 끌어다
놓으면 그 한 장만 다시 인식되고, 나머지 사진의 결과는 그대로 유지됩니다.

## 진행 상태 저장 (localStorage)

`src/utils/persist.js`가 선택한 캐릭터·현재 화면·에코 세팅(스탯, 미리보기 이미지)을 브라우저의
localStorage에 저장합니다. 값이 바뀔 때마다 자동으로 저장되고, 앱을 다시 열면 마지막 상태를 그대로
복원합니다. 미리보기 이미지는 base64 문자열(dataURL)로 저장되어 새로고침 후에도 깨지지 않습니다.
저장을 초기화하고 싶으면 브라우저 개발자 도구 콘솔에서 `localStorage.removeItem('wuwa-echo-check:v1')`
를 실행하면 됩니다.

## 캐릭터별 저장 및 재방문

`characterData`는 캐릭터 id별로 에코 세팅을 따로 보관합니다(`{ [id]: echo[] }`). 캐릭터 선택 화면에서
카드를 클릭하면:
- 그 캐릭터에 저장된 에코가 있으면 **캡처를 건너뛰고 바로 점수 통계 화면**으로 이동합니다.
- 없으면 평소처럼 캡처 화면으로 이동합니다.

캐릭터 카드에는 저장된 데이터가 있을 경우 평균 %점수가 사진 오른쪽 위에 배지로 표시됩니다.

## 확인 모달 (초기화) / 미선택 스탯 알럿

`src/components/ConfirmDialog.jsx`는 예/아니요 확인창이 필요한 곳(점수 통계 화면의 "초기화" 버튼)에
씁니다. 스탯 미선택은 확인창이 아니라 **알럿 + 하늘색 강조**로 처리됩니다:
- 수정 화면에서 라벨이나 수치를 안 고른 서브 스탯이 있는 채로 "점수 통계 보기"를 누르면 알럿이 뜨고
  다음 화면으로 넘어가지 않습니다. 안 채운 칸에는 하늘색 테두리가 표시됩니다.
- 점수 통계 화면의 "초기화" 버튼을 누르면 확인창이 뜨고, 예를 누르면 **그 캐릭터의 저장된 에코
  데이터만** 지우고 캐릭터 선택 화면으로 돌아갑니다(다른 캐릭터의 데이터는 유지됩니다).

## 캐릭터 선택 카드 디자인

캐릭터 카드가 610×840 세로 사진을 그대로 보여주는 형태로 바뀌었고, 사진 아래에는
"이름 | 속성"이 표시됩니다. 속성은 현재 6가지(응결/용융/전도/기류/회절/인멸) 중 하나이며,
`src/config/characters.js`의 `element` 필드로 지정합니다.

## 서브 스탯 중복 선택 방지

한 에코 안에서 같은 스탯명을 두 번 이상 고를 수 없습니다. 이미 다른 줄에서 선택된 스탯명은 그 줄의
드롭다운에서 자동으로 빠집니다(`EchoPanel.jsx`).

## 합산 스탯 (오른쪽 컬럼)

`computeFullAggregate`(`StatsPage.jsx`)가 유효 옵션 여부와 무관하게 캡처된 모든 서브스탯을 13개
카테고리로 묶습니다. 카테고리와 우리 카탈로그 라벨의 매칭은 `CATEGORY_MATCH`에서 관리하며, 아직
카탈로그에 없는 카테고리(조화도 파괴 증폭·속성 피해 보너스·에코 피해)는 항상 "-"로 표시됩니다.

계산 규칙: **%는 먼저 전부 더하고**, 같은 카테고리에 **플랫 값이 하나라도 있으면** 그 합산 %를
플랫에 적용한 값(`플랫 합계 × (1 + %합계/100)`, 소수 첫째 자리에서 올림) **하나만** 최종 숫자로
보여줍니다. 플랫이 없으면 %합계만, 아무것도 없으면 "-"를 표시합니다.

## 목표 스탯 계산기

합산 스탯 아래에 있는 계산기(`src/utils/optimizer.js`)는 공격력/방어력/HP 중 하나를 골라 **기준
스탯**(에코 적용 전 순수 수치)과 **목표 스탯**을 입력하면:
- 지금까지 캡처된 % 합계·플랫 합계를 반영한 현재 예상 총합을 보여주고,
- 목표까지 남은 상승분(%)을 계산하고,
- 남은 서브 스탯을 전부 8단계로 채웠을 때(최선)와 전부 1단계로 채웠을 때(최악) 각각 몇 개가 더
  필요한지 추정치를 보여줍니다.

⚠️ 이건 정확한 조합 최적화(어떤 에코의 어떤 자리에 뭘 넣어야 하는지)가 아니라, "%당 기여도가 가장
높은 옵션부터 채운다면"이라는 단순 근사치입니다. 슬롯 개수나 다른 스탯과의 우선순위까지 고려한
정밀한 최적화가 필요하면 알려주세요 — 별도로 더 다듬어드릴 수 있어요.

## 에코 목록 (가운데 컬럼)

이제 클릭해서 펼치는 방식이 아니라, 모든 에코의 서브 스탯이 **항상 전부 펼쳐진 채로** 보입니다.
라벨은 잘리지 않고 필요하면 줄바꿈되어 "공명 해방 피해 보너스%" 같은 긴 이름도 그대로 보입니다.
개별 에코의 %점수 표시는 없앴습니다(합산 스탯·목표 스탯 계산기가 그 역할을 대신합니다).

## 캐릭터 목록 (56명) + 검색/필터

`src/config/characters.js`에 4성 12명 + 5성 44명(방랑자 속성별 변형 포함) 전체가 들어 있습니다.
캐릭터 선택 화면에서:
- **검색창**: 이름에 입력한 글자가 포함되면 바로 걸러집니다(예: "능" → 능양).
- **성급 필터**: 전체 / 5성 / 4성
- **속성 필터**: 전체 / 응결·용융·전도·기류·회절·인멸 — 단, 지금은 모든 캐릭터가 **임시로 회절**로
  지정돼 있습니다(`element` 필드). 실제 속성을 알려주시면 정확히 채워드릴게요.
- 사진이 없는 캐릭터는 이니셜 아바타로 표시됩니다. 나중에 사진을 추가하려면 위 "캐릭터 사진 추가"
  순서대로 `raw-characters/`에 넣고 `npm run prepare-characters` 실행 후 `characters.js`의 해당
  캐릭터 `image` 값만 채우면 됩니다.

## 엑셀에서 가져온 캐릭터별 유효 옵션

`src/config/characterValidOptions.js`는 업로드해주신 "명조 스펙 계산기" 엑셀의 `공명자 정보` 시트
(주스탯 · 피해 유형)를 기준으로 자동 생성했습니다: 크리티컬% · 크리티컬 피해% · 주스탯%(공격력%/
방어력%/HP%) · 그 캐릭터의 피해 유형에 대응하는 보너스% · 공명 효율%(참고용, 점수엔 미반영).
엑셀에 해당 캐릭터 정보가 없던 경우(4성 전체, 능양/앙코/카카루/감심/방랑자·전도)는 크리티컬%·
크리티컬 피해%·공격력%·공명 효율%로 기본값을 넣어뒀습니다 — 실제 세팅을 알려주시면 정확히 채워드릴게요.

## 목표 스탯 계산기 / 무기·에코 세트 / 넓은 화면 레이아웃 (최신)

- **레이아웃**: `.app` 최대 폭을 1400px로 넓혔고, 점수 통계 화면은 왼쪽(캐릭터)·가운데(합산 스탯 +
  목표 스탯 계산기)·오른쪽(에코 점수, 더 넓게) 3단으로 재배치했습니다.
- **무기·에코 세트**: 캐릭터 이름 아래 "사용 무기"(텍스트 입력 1개), "사용 에코 세트"(최대 3개, 칩
  형태로 추가/삭제)를 입력할 수 있습니다. 캐릭터별로 저장됩니다.
- **합산 스탯**: 이제 메인 스탯도 함께 합산되고, "조화도 파괴 증폭"·"에코 피해" 행은 뺐습니다.
  HP·공격력·방어력은 (기준값 × 배율) + 플랫을 자동으로 곱하지 않고 **기준/배율/플랫 세 값을
  각각** 보여줍니다(기준값은 그 자리에서 입력·수정 가능, 검수용).
- **목표 스탯 계산기**(`src/utils/optimizer.js`): HP·공격력·방어력·공명 효율·크리티컬·크리티컬
  피해 중 목표를 정하고 **"계산하기" 버튼을 눌러야** 동작합니다. 목표가 0이면 계산하지 않습니다.
  1순위로 기존 에코를 건드리지 않고 빈 자리에 채우는 방법을, 부족하면 2순위로 이미 있는 스탯을
  최고 단계로 올리는(민맥싱) 방법을 "에코 N의 ○○를 △△로" 식으로 알려줍니다. 어떤 에코부터
  건드릴지는 유효 옵션이 가장 적은 에코 → 그다음 스탯 값 합계가 가장 낮은 에코 순으로 고릅니다.
  ⚠️ 정확한 조합 최적화는 아니고 "최고 단계부터 채운다면"이라는 근사치입니다.
- **초기화 동작 변경**: 이제 초기화하면 캐릭터 선택 화면이 아니라 **그 캐릭터의 캡처 화면**으로
  돌아갑니다(무기·에코 세트·기준 스탯 값은 유지, 에코 캡처 데이터만 지워집니다).
- **에코 점수**: 이제 각 에코의 **주 스탯**도 함께 표시됩니다.

## 무기 / 에코 세트 팝업, 자동 합산, 레이아웃 재배치 (최신)

- **무기·에코 세트가 카탈로그 기반으로 변경**: `src/config/weapons.js`, `src/config/echoSets.js`에
  데이터를 정의하고, 캐릭터 카드에서 "무기 선택"/"에코 세트 추가" 버튼을 누르면 **팝업(Modal)**으로
  고를 수 있습니다. 에코 세트는 2세트/5세트 중 골라서 최대 3개까지 추가할 수 있고(1세트는 UI에서
  뺐습니다), 5세트를 고르면 2세트 효과도 함께 적용됩니다.
- **캐릭터 기초 스탯 자동 반영**: `src/config/characterBaseStats.js`에 캐릭터별 기초 HP·공격력·
  방어력·공명 효율·크리티컬·크리티컬 피해와, 캐릭터 고유 스킬로 항상 붙는 % 보너스(예: 에이메스
  크리티컬 +8%·공격력 +12%)를 정의합니다. 더 이상 직접 입력하지 않고, 여기 있는 캐릭터를 선택하면
  자동으로 채워집니다. 없는 캐릭터는 0으로 나오니 알려주시면 추가해드릴게요.
- **합산 공식**: 공격력 = (캐릭터 기초 공격력 + 무기 공격력) × (1 + 캐릭터·무기·에코 세트·에코에서
  모은 %) + 에코 플랫. HP·방어력도 무기 항만 빠지고 동일합니다. 무기를 바꾸거나 에코 세트를
  추가/삭제하면 자동으로 다시 계산됩니다. 표에는 "합산"(최종 수치)과 "내역"(회색 기초값 + 색깔 있는
  추가분)을 같이 보여줍니다.
- **레이아웃 재배치**: 에코 카드들이 화면 맨 위에 가로로 나열되고(주 스탯 2줄 + 서브 스탯), 그 아래
  4단으로 캐릭터 정보 / (디자인만 잡아둔 빈 칸) / 목표 스탯 계산기 / 합산 스탯이 배치됩니다.

## 에코 직접 편집, 목표 계산기 재설계, 반올림 규칙 (최신)

- **상단 에코 카드가 이제 진짜로 편집 가능**: 수정 화면에서 쓰던 `EchoPanel` 컴포넌트를 그대로
  재사용해서, 점수 통계 화면 맨 위에서도 서브 스탯을 바로 고칠 수 있습니다(단계 배지는 안 보여요).
- **에코 세트는 2세트만 계산**: 5세트 옵션은 없앴습니다(항상 2세트만 장착했다고 가정).
- **무기/에코 세트 선택 팝업 단순화**: 아이콘 + 이름만 보이고, 무기는 캐릭터의 `weaponType`(예:
  에이메스=직검)과 일치하는 것만 목록에 뜹니다. 사용 중인 에코 세트에 마우스를 올리면 (i) 아이콘으로
  세트 효과 설명이 뜹니다.
- **반올림 규칙**: HP는 소수점 무조건 올림, 나머지 스탯은 전부 내림으로 표시합니다
  (`formatByCategory`).
- **목표 스탯 계산기 재설계**: 드롭다운 대신 HP·공격력·방어력·크리티컬·크리티컬 피해·공명 효율
  6칸을 한 번에 입력하고, "계산하기" 한 번으로 전부 계산합니다. 기준값을 따로 입력할 필요 없이
  이미 계산된 "합산 스탯"을 그대로 사용합니다.
- **"추가 예정" 칸에 예전 에코 점수표**를 넣었습니다(라벨|값 형태의 간단한 목록).
- **합산 스탯 순서**: "에코 피해"가 맨 아래로 내려갔습니다.

  폭 확장으로 고쳤습니다.

## 유효 옵션 위치, 반올림 규칙, 목표 계산기 우선순위 (최신)

- **"유효 옵션" 목록이 에코 탭 아래로 이동**했습니다(캐릭터 카드에서 뺐어요).
- **반올림 규칙 정리**: HP·공격력·방어력만 정수로 올림/내림 처리하고, 나머지 전부(공명 효율·
  크리티컬·크리티컬 피해 포함)는 항상 소수점 한 자리로 표기합니다(`formatWholeStat`/
  `formatPercent1`, 예: `1.0%`).
- **목표 스탯 계산기 우선순위 변경**: 1순위가 "빈 자리 채우기 → 그래도 자리가 꽉 찼으면 유효
  옵션이 아닌 스탯을 찾아 교체"로 바뀌었습니다(둘 다 기존 유효 옵션은 안 건드리는 동일한 그룹).
  2순위는 그대로 민맥싱(단계 업그레이드)입니다. 추천 문구도 "에코 N의 유효 옵션이 아닌 방어력
  (50)을 크리티컬% 10.5%로 교체" 식으로 나옵니다.
- 에코 세트 5세트 설명에서 "(조건부 효과를 상시 적용한다고 가정해 계산합니다)" 문구를 뺐습니다.

## 무기 카드, 5세트 미적용, 최소 단계 추천, 유효/추천 강조 (최신)

- **메인 스탯도 이미 합산에 포함되어 있었어요** — `computeAggregate`가 처음부터 `echo.mainStats`도
  같이 더하고 있었습니다. 새로 손댈 부분은 없었어요.
- **에코 세트 5세트는 계산에서 빠집니다**: 2세트 효과만 실제로 더해지고, 5세트를 선택해도 카드에는
  "(계산에는 반영되지 않아요)" 안내만 붙습니다.
- **무기도 에코 세트처럼 설명 카드가 붙습니다**: `[별을 좇아서]` 같은 패시브 이름 + 전체 설명 텍스트가
  뜨지만, 실제로 계산에 반영되는 수치는 여전히 속성 피해 보너스 12%뿐입니다(방어력·저항 무시 효과는
  안내 문구로만 표시).
- **목표 스탯 계산기가 항상 최고 단계만 추천하던 문제 수정**: 이제 그 시점에 남은 필요량을 채우는
  "가장 낮은 단계"부터 고릅니다(`pickSufficientTier`). 남은 필요량이 최고 단계보다 크면 그때만
  최고 단계를 씁니다.
- **에코 편집 화면에 색으로 표시**: 유효 옵션에 해당하는 서브 스탯은 노란 테두리, 계산 결과가 "교체"나
  "업그레이드"를 추천한 스탯은 하늘색 테두리로 표시됩니다(선택된 에코 탭 기준).
- **유효 옵션 목록은 다시 캐릭터 카드 아래로** 옮겼습니다.

## GitHub Pages 배포

1. GitHub에 새 저장소 생성 후 이 프로젝트 push
2. `vite.config.js`의 `base`를 저장소 이름에 맞게 설정
   ```js
   base: '/저장소이름/',
   ```
3. 배포
   ```
   npm run build
   npm run deploy
   ```
   (`gh-pages` 패키지가 `dist` 폴더를 `gh-pages` 브랜치로 자동 push 합니다)
4. 저장소 Settings → Pages에서 배포된 URL 확인
